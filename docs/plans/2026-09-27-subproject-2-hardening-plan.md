## How to work this plan

The runbook applies as written, with these changes:

- **Model.** Every worker on `opus`.
- **Surface first.** Each worker commits its new API as a behaviour-free surface commit, then tests and behaviour, and
  proves at it (worker brief pitfall 10). Workers run `swiftgate surface-check <surface sha>` on it too.
- **Merge gate.** Push + `prove --base main` on 1 integration worktree. With more than 1 surfaced branch in a wave,
  merge every surface commit first and prove at that merge. Mutate runs once on `main` after the wave.
- **Id policy.** Task ids and wave numbers never appear in code, comments, test names or commit messages.
- **Paths.** `D/` = `plugin/gate/Sources/SwiftGateDomain/`, `A/` = `plugin/gate/Sources/SwiftGateAdapters/`,
  `C/` = `plugin/gate/Sources/SwiftGateCLI/`, `R/` = `plugin/gate/Sources/SwiftGateRules/`,
  `TD/` `TA/` `TC/` `TR/` = `plugin/gate/Tests/SwiftGate{Domain,Adapters,CLI,Rules}Tests/`, `GF/` = `plugin/gate/Fixtures/`,
  `TF/` = `plugin/gate/Tests/Fixtures/`, `P/` = `plugin/`.
- **Prompt edits.** A task that edits `P/agents/build-*.md` or `P/workflows/design-*.js` makes a calibration record
  stale. Its worker re-runs `calibrate build` or `calibrate design` and commits the record it writes.
- **Budgets.** A task that adds rows to `plugin/docs/standards.md` re-measures `docs-lint`. If the file goes over its
  `[docs.budgets.files]` row, raise that row in `.swiftgate.toml` in the same commit, and name it in DEVIATIONS.
