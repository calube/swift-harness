## Before wave 1: the judge audit log

Merged as ef5832d. Where it differs from the design, the code wins, and the design follows at the next docs task.
- Envelope `HarnessEvent {schemaVersion, eventID, parentID?, kind, time, runID?, head?, base?, source: {route?, tier?, hook?}, payload}`. A missing `route` means unattributed.
- Kinds map to streams through `HarnessEventKind.stream`, and each stream is 1 file: both `judge.decision` and `judge.call` go to `.harness/events/judge.jsonl`, not 1 file per kind. Each run also keeps a copy at `.harness/runs/<id>/events/judge.jsonl`.
- The writer protocol is `HarnessEventWriting`; `HarnessEventFiles` stores it. A failed write is the nit `judge-events.unwritten` and never changes the verdict.
- Judge reasons and rationales can exceed the design's 512-byte payload guard. The guard must not drop or truncate a judge decision's reason: the judge log is the audit trail, and it stays on under `[telemetry] enabled = false` (user, 2026-09-30).
- Routes: `check-ready`, `judge-tests`, `judge-tests-ready`, `comment-hook`, `calibrate-design`, `judge-ask`, `bench`, `self-test`. A `judge.call`'s `role` is `answer`, `escalation` (parent: the Jev call) or `reason` (parent: the block's decision).
- `swiftgate judge events [--since <runID|ISO>] [--run <id>] [--route r] [--backend b] [--json]` exits 0, 2 for bad input or a newer schema, and 64 for an unparseable flag. The route table is in `plugin/docs/judge-audit.md`.
- `.harness/events/` is git-ignored here and in `plugin/templates/gitignore`.

## Wave 1

- `xunit-and-xcresult-carry-durations` (583cee6): `XUnitTestCase.milliseconds: Int?` and `XcresultTestCase.milliseconds: Int?`, each init's last parameter defaulting to `nil`. The value is `Int(exactly: (seconds * 1000).rounded())`; NaN, infinity or an unparseable time gives `nil`. Swift Testing cases under 0.5 ms give `0`.
- `throwaway-session-usage-is-captured` (26441ba): fixtures in `plugin/gate/Tests/Fixtures/Transcripts/`, capture recorded in the fixtures README. Claude Code keeps a main transcript as `<session_id>.jsonl` in its per-project directory, and a subagent's as `<session_id>/subagents/agent-<id>.jsonl`; the fixtures README names the directory. Usage keys: `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `cache_creation.ephemeral_{5m,1h}_input_tokens`. A message with 2 content blocks gives 2 lines with the same `message.id` and usage; usage deduplicated by message id equals the envelope's `modelUsage`. The envelopes solve to $4 input, $5 5-minute cache write and $0.20 cache read per million tokens for `claude-opus-5-5`; the output price was not confirmed.
- `telemetry-is-on-unless-opted-out` (4a057df): `TelemetryConfig { enabled: Bool = true }` on `Config.telemetry`, the last `Config.init` parameter. The TOML key is `[telemetry] enabled`; config issues use the paths `telemetry`, `telemetry.enabled` and `telemetry.<unknown>`. The commented `[telemetry]` table isn't in `plugin/templates/swiftgate.toml` yet; the docs task adds it.
- `event-store-guards-rotates-and-seals` (e9e3bd5): live segments rotate into `sealed/<stream>/<seq>.jsonl`, then `.jsonl.lzfse` plus `.index.json`; the store keeps `store.json`, `dropped.json` and `store.lock`. Rotation is at 4 MiB for the judge stream and `EventSegmentLayout.largeRotationBytes` (16 MiB) for `test.result`. `HarnessEventWriting.append(contentsOf:)` makes 1 write per stream; a guard drop throws `HarnessEventWriteError` naming the kind and the reason. `EventWriterFactory.make(root:enabled:)` returns `DisabledEventWriter` when off. The judge stream is exempt from the payload guard and keeps using `HarnessEventFiles` directly, so the opt-out never silences it. Real `test.result`-shaped lines compress about 9.7 times.

## Wave 2

- `events-list-and-summary-read-every-store` (876bd81): a summary section is `struct X: EventSummarySection { var id: EventSummarySectionID; func summarize(_ input: EventSummaryInput) -> EventSummarySectionReport? }`, and `nil` prints "no events yet". `EventSummaryInput` holds `events: [StoredEvent]`, `query: EventQuery` (with `buildRunID`), `store: EventStoreFacts`, `damage: [EventDamage]`, `files: any EventStoreFileReading` (paths relative to the worktree) and `now`. Metrics are `EventSummaryMetric {name, group, value, unit, n}`. `events list [--kind k]... [--since 7d|12h|30m|ISO|runID] [--run id]` prints JSON lines; `events summary [--since 7d] [--run id] [--build-run id] [--json]`. Both exit 0 even with damage, 2 for a bad flag value and 64 for a flag that doesn't parse. `judge events` doesn't read `imported/` yet.
- `gate-runs-record-tree-and-steps` (404e553): stream `gate`, route `check`, kinds `gate.run` and `gate.step`. `gate.run` payload: `command?`, `verdict`, `ms`, `treeHash?`, `dirty?`, `tiers[{tier,verdict,ms}]`, `ruleCounts`, `findingPaths`, `findingPathsTruncated`, `allowanceCounts`, `testCounts?`; no finding message text. `gate.step` payload: `tier?`, `step`, `ms`, `verdict`, `derivedData` (`warm`, `cold` or `none`). `GateStep` values: `resolve`, `lint`, `testlint`, `arch`, `format`, `impact`, `test`, `coverage`, `app-build`, `reach`, `stress`, `prove`, `mutate`, `judge`, `simulator`, `docs`, `plugin-validate`, `record`. `RunStore.record` takes `gateSteps:`; a failed event write throws `RunStoreError.eventsUnwritten`, which `GateRun.record` catches so the verdict stands. Adding a kind touches `HarnessEvent.swift`, `EventPayloadGuard.swift`, `EventSegmentIndex.swift`, `JudgeEventSummary.swift` and `RuleIDSourceScan.swift`: the hook and cache tasks merge one after the other.
- `worktree-remove-copies-events-up` (368d4e8): `worktree remove` copies every stream to `.harness/events/imported/<storeID>/`, replacing an earlier import only when the source holds more bytes. If the copy fails it moves the events to `.harness/events/unkept/<storeID>/` (or the git common dir's `swift-harness/unkept-events/<storeID>/` across volumes). The remove report adds `events {storeID, path, bytes, copied}` and `unkeptEvents`; exit codes don't change. `events` and `judge events` read `imported/` and `unkept/`, deduplicated by `eventID`, but not yet the common-dir fallback. `gc --events --older-than <days>` takes both flags together (at least 1 day, else exit 64); read or remove errors exit 2.
